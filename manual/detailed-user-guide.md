# 상세 사용자 설명서

## 화면 구조

- 첫 화면: 학교 작업공간 생성
- 학교 화면: 회차 생성, 파일 업로드, 수기 입력
- 검수 화면: 후보 확정, 제외, 수정, 엑셀 출력
- 설정 화면: 알라딘 API 키, OCR 경로

## 학교별 데이터 보관 방식

학교별 데이터는 `workspace/<학교명>/` 아래에 저장됩니다.

- `holdings/raw/`: DLS 소장목록 원본 보관
- `recommendations/raw/`: 추천도서 원본 보관
- `manual/manual_entries.xlsx`: ISBN, 제목/저자 수기 입력 보관
- `catalog/catalog_master.xlsx`: 누적 서지 캐시
- `sessions/<연도-회차>/review_state.json`: 검수 상태
- `sessions/<연도-회차>/통합검수결과.xlsx`: 중간 결과
- `sessions/<연도-회차>/최종수서목록.xlsx`: 최종 제출용 파일

앱 폴더를 새 버전으로 교체할 때는 `workspace` 폴더만 유지하면 기존 작업이 이어집니다.

## 추천목록 처리 기준

### 엑셀

- 여러 기관의 추천목록은 헤더 위치가 달라도 자동 탐지합니다.
- `도서명`, `도서 제목`, `자료명` 등 유사 컬럼을 같은 표준 필드로 합칩니다.

### PDF

- 텍스트형 PDF는 표 추출을 먼저 시도합니다.
- 실패하면 OCR로 다시 읽습니다.
- OCR 결과가 불안정하면 `검토필요` 로 보냅니다.

### 수기 입력

- ISBN만 입력해도 알라딘 조회로 기본 서지를 채웁니다.
- 제목과 저자만 입력하면 통합 후 후보 검색 대상으로 남습니다.

## 복본 검사 기준

1. ISBN 일치
2. 제목 + 저자 정규화 일치
3. 제목/저자 유사도 높음

1번과 2번은 자동으로 `복본-기소장` 으로 분류합니다.
3번은 자동 제외하지 않고 `검토필요-유사서명` 으로 보냅니다.

## 검수 화면 사용법

- `선택`: 최종 엑셀에 포함할지 여부
- `상태`: 최종구매후보, 검토필요, 복본-기소장 중 하나로 재분류
- `행 저장`: 현재 행의 수정 내용을 저장
- `ISBN/서지 다시 조회`: 제목/저자 기준으로 알라딘 후보를 다시 찾음
- `후보 적용`: 후보 서지로 제목, 저자, 출판사, ISBN 등을 교체

## 추천 출처 처리

같은 도서가 여러 기관에 추천되면 한 건으로 합치고 `추천건수`, `추천기관`, `추천파일` 을 함께 저장합니다.

## 최종 엑셀 출력 형식

최종 엑셀은 다음 열 순서를 유지합니다.

`NO.`, `도서명`, `지은이`, `출판사`, `ISBN`, `정가`, `쪽수`, `출판일`, `분류`, `목록출처`

## 문제 해결

### 알라딘 조회가 안 될 때

- 설정 화면에서 API 키를 다시 확인합니다.
- 인터넷 연결을 확인합니다.
- 그래도 안 되면 수동 검수로 진행하고 나중에 다시 조회합니다.

### PDF가 거의 안 읽힐 때

- 스캔 품질이 낮은 경우입니다.
- 가능하면 엑셀 원본을 우선 사용합니다.
- PDF만 있다면 OCR 후 검토필요 항목을 수동 정리합니다.

### 최종 엑셀이 비어 있을 때

- 검수 화면에서 `선택` 이 체크되어 있는지 확인합니다.
- 모든 행이 `복본-기소장` 이나 `검토필요` 로 들어갔을 수 있습니다.
