# 추천목록 통합과 일괄 검토 설계

## 목표와 판단

사서가 기관마다 다른 추천목록을 한꺼번에 모으고, 반복 입력과 반복 확인을 줄여 수서 판단에 집중하도록 한다. 사용자가 요청한 설계와 구현을 함께 수행한다. 최신 제품 진입점인 2.1.2 개인용 앱을 기준으로 하며 기존 배포본과 사용자 자료는 변경하지 않는다.

별도 전처리 프로그램에서 표준 엑셀을 만들어 다시 업로드하는 방식은 작업·오류·파일 버전을 늘린다. 따라서 **원본 업로드 → 자동 표준화 → 예외만 수정 → 한 번에 통합**을 앱 안에서 제공한다. 표준화는 내부 데이터 계약이며 사서의 추가 의무가 아니다. 임의 형식의 문서를 무조건 정확히 읽는다고 약속하지 않는다.

## 사용자 흐름

1. 추천목록 여러 파일을 선택한다. 파일별로 순차 해석하며 진행 상황과 실패를 표시한다. 하나의 실패로 성공한 미리보기를 잃지 않는다.
2. 엑셀·CSV·PDF·HWP·HWPX·DOCX·텍스트의 기존 파서를 재사용한다. 제목·저자·출판사·ISBN·가격·수량·출처 등 표준 필드에 연결하며 파일별 열 연결과 원문 위치를 수정·확인할 수 있다.
3. 기본으로 같은 책 합치기를 켠다. 모든 파일의 선택한 행을 하나의 트랜잭션으로 넣는다. 신규 종수와 합친 행 수를 구분해 알려준다. 기존 구입 목록과도 대조한다.
4. ISBN이 없어도 제목·저자·출판사와 가격이 확인된 구조화 자료는 즉시 사용 가능하다. ISBN 누락만으로 확인 필요를 만들지 않는다. 입력된 잘못된 ISBN, 가격 누락, OCR·수식·열 해석 불확실성은 별개 사유다.
5. 목록에서 구입 체크와 별개로 일괄 작업 대상을 고른다. 현재 검색·필터 전체 선택, 선택한 도서 서지 확인 완료, 구입 선택, 보류를 제공한다. 현재 페이지와 필터 전체의 범위를 명확히 표시한다.
6. 일괄 확인은 사서의 원문 확인을 기록한다. 필수 식별 정보·가격이 없거나 ISBN이 잘못된 행은 남기고 이유를 알려준다. 개별 도서를 200번 열 필요가 없다. 일괄 작업과 통합 가져오기는 되돌릴 수 있다.

## 동일 도서 판단과 기록

- ISBN 10/13은 검증 후 같은 ISBN13으로 비교한다.
- ISBN 없는 책은 제목·저자·출판사·발행일의 보수적인 정확 일치를 사용한다. 숫자·권차·개정판·문장부호를 임의로 제거하지 않는다.
- 다른 유효 ISBN, 충돌하는 서지·가격은 자동으로 버리지 않고 검토할 수 있게 남긴다. 제목만 같다고 합치지 않는다.
- 추천 횟수와 구입 수량은 다르다. 합칠 때 수량을 합산하지 않으며 기존 구입 여부·검토 완료·가격을 임의로 덮어쓰지 않는다.
- 원본 파일·행·시트·원문·추천 출처를 기여 기록으로 보존한다. 다시 가져오기 요청에는 요청 식별자를 사용해 통신 재시도가 중복 삽입을 만들지 않게 한다.
- 되돌리기는 작업 전후 스냅샷을 비교한다. 이후 편집이 있으면 이를 덮어쓰지 않고 되돌리기를 거부한다.

## 속도와 실패 처리

외부 조회는 업로드의 필수 단계가 아니다. 기존 ISBN 기반 빈 정보 채우기는 명시적으로 실행하고 회당 50권, 진행 표시와 중지 기능을 유지한다. 제목만으로 임의 ISBN을 자동 확정하지 않는다. 캐시와 기존 조회 경로를 재사용한다.

파일은 한 번에 하나씩 파싱하고 일괄 저장은 총 20,000행까지 제한한다. 중복 탐색은 키 인덱스를 사용하며 전체 행 쌍을 비교하지 않는다. 미리보기와 목록의 DOM은 페이지 단위로 제한한다. 소장목록 교체는 추천 합치기와 구분하고 한 파일 단위로 명확히 안내한다.

## 검증 및 현실적 범위

합성 자료로 교차 파일 중복, ISBN 없는 200권 확인, 다른 판본·권차, 가격 충돌, 부분 파일 실패, 거래 원자성, 재시도, 되돌리기, 검색 범위 선택, 대량 페이지 표시를 검증한다. 공개 실습 자료로 열 탐지와 인식 결과를 확인한다. 실제 학교의 처리 시간 단축은 자료 품질·선정 심의에 따라 달라지므로 ‘하루 완료’를 성능 보장으로 주장하지 않는다. 공개 배포와 설치는 별도 단계이며 이번 변경은 실행·검증 가능한 코드와 로컬 빌드로 제공한다.
