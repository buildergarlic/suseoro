# 도서 작업 화면 재구성 설계

## 목적과 승인

2026-09-25 사용자 승인: A안(도서 작업표). 기존 화면에서 도서 목록이 아래로 밀려 한 번에 약 세 권만 보이는 문제를 해결한다. 최신 개인용 앱 2.1.2의 화면과 저장 자료를 대상으로 한다.

## 화면 구조

- 왼쪽 고정 메뉴에 학교명, 구입 목록 전환과 생성, 현재 목록의 예산·선택금액·잔액, ISBN 추가·파일 가져오기·발주서 저장, 등록 자료 열람 메뉴, 표시 설정·학교 설정·도움말을 둔다.
- 오른쪽 본문은 짧은 제목과 검색·상태 필터 다음에 도서 표가 남은 창 높이를 채운다. 본문 위에 별도 예산 카드와 큰 소개 문구를 쌓지 않는다.
- 도서 행은 제목·저자·출판사·ISBN·소장 상태 등 필요한 정보를 읽기 쉬운 짧은 묶음으로 보여 준다. 표지를 작게 하고 상세 편집은 기존 오른쪽 서랍을 쓴다. 표 머리글과 검색 도구는 목록을 스크롤할 때 계속 사용할 수 있어야 한다.
- 16~24px 글자 크기와 행 간격 설정을 유지한다. 좁은 창에서는 메뉴를 접거나 재배치해 가로·세로 스크롤의 중첩을 피한다.

## 등록 자료 열람

- `학교 소장목록`은 모든 구입 목록이 공유하는 현재 소장자료를 읽기 전용으로 보여 준다. 제목·저자·ISBN·출판사·출처 검색과 페이지 이동을 제공한다. 기존 소장목록 갱신 동작은 유지한다.
- `추천도서 목록`은 현재 선택된 구입 목록에 등록된 도서를 출처별로 모아 읽기 전용으로 보여 준다. 기존 데이터는 원본 파일과 최종 등록 관계가 저장되지 않으므로 등록 도서의 `source` 값을 기준으로 묶는다. 원본 파일 전체 또는 취소된 가져오기 미리보기를 등록 자료로 주장하지 않는다.
- 등록 자료 화면에서 구입 목록으로 돌아갈 수 있고, 추천도서 화면의 목록 전환은 현재 선택한 구입 목록을 따른다. 가져오기·백업 복원 후 열람 내용은 새로고침된다.

## 데이터와 검증

- 소장자료 조회 API는 검색·페이지 단위로 반환한다. 최대 100,000행 전체를 브라우저에 내려보내지 않는다. 조회 API는 기존 소장 대조·교체와 구입 선택 상태를 바꾸지 않는다.
- 기존 구입 선택, 도서 수정, 가져오기, 발주서 저장, 글자 크기와 검색 단축키 동작을 보존한다.
- 화면 내비게이션과 조회 API를 자동 테스트하고, 실제 브라우저에서 1366×768 및 큰 창의 목록 높이·좁은 창 재배치를 확인한다.
