# 수서로 v2 제품 명세

상태: 승인됨

기준일: 2026-08-28

제품 문장: **추천자료를 넣으면 우리 도서관에 없는 책을 찾아주고, 승인·발주·납품 검수까지 이어서 도와드립니다.**

## 1. 제품 목표와 범위

수서로 v2는 학교도서관 사서가 서로 다른 형식의 추천도서 목록과 학교의 실제 소장목록을 비교해 수서 후보를 만들고, 승인·견적·발주파일·납품 검수까지 한 작업에서 끝내는 교내망 서비스다.

이번 버전에 포함한다.

- 학교 한 곳, 동시 사용자 약 10명, 장서 최대 20만 권
- 담당자와 검토자의 공동 사용 및 승인 이력
- 추천자료와 소장자료의 자동 인식·파싱·열 연결·양식 기억
- XLS/XLSX/XLSB/ODS/CSV/TSV/PDF/TXT/DOCX/HWPX/HWP 및 텍스트 붙여넣기
- DLS MARC 전체·증분 및 DLS Excel 전체 스냅샷
- 로컬 장서 비교, 후보 검토, 견적 비교, 발주파일, 납품명세서, ISBN 바코드 검수
- v1 `workspace` 읽기 전용 보존과 안전한 이전
- 교내 Windows 서버 설치, 백업·복원·업데이트 전 보호 절차

이번 버전에서 제외한다.

- S2B·나라장터·업체로 실제 주문 전송
- 학생·대출자·대출이력 수집
- DLS 도서 등록, 라벨 출력
- 비승인 DLS API 호출이나 웹 크롤링
- DLS 승인 없이 학교 장서를 외부 서비스 장서로 대체

## 2. 사용자와 화면

역할은 두 개다.

- `OPERATOR`: 자료, 후보, 견적, 발주, 납품을 편집한다.
- `REVIEWER`: 요청된 버전을 보고 의견, 승인, 수정 요청을 수행한다.

자기 승인은 기본 금지다. 학교 설정에서 `1인 운영`을 명시적으로 켠 경우만 같은 사용자가 두 역할을 겸한다.

사용자가 보는 최상위 화면은 세 개뿐이다.

1. `로그인`
2. `내 수서 업무`
3. `수서 작업실`

수서 작업실은 현재 과정만 펼치고 완료 과정은 한 줄로 접는다.

```text
1. 후보 만들기             2. 승인·발주              3. 납품 검수
자료 → 없는 책 → 확정      승인 → 견적 → 발주파일    명세서 → 바코드 → 완료
```

별도 저장·다음 버튼은 두지 않는다. 편집은 자동 저장하며 `저장됨 HH:MM`을 표시한다. 정상 반복 작업은 담당자 주요 조작 10회 이하, 검토자는 요청 열기와 승인까지 2회 이하다. 바코드 사이에는 추가 클릭이 없어야 한다.

## 3. 사용자 상태와 전이

내부 상태와 사용자 표시는 다음으로 고정한다.

| 내부 상태 | 사용자 표시 | 담당 | 주요 다음 행동 |
| --- | --- | --- | --- |
| `DRAFT` | 자료 준비 중 | 담당자 | 우리 도서관에 없는 책 찾기 |
| `ANALYZING` | 도서 비교 중 | 시스템 | 완료 후 자동 이동 |
| `CANDIDATE_REVIEW` | 후보 확인 중 | 담당자 | 후보 확정하고 승인 요청 |
| `APPROVAL_PENDING` | 승인 기다리는 중 | 검토자 | 이 목록 승인 / 수정 요청 보내기 |
| `CHANGES_REQUESTED` | 수정 요청됨 | 담당자 | 수정 완료하고 다시 승인 요청 |
| `APPROVED` | 승인됨 | 담당자 | 견적서 넣기 |
| `QUOTE_REVIEW` | 견적·예산 조정 중 | 담당자 | 이 견적 사용 |
| `ORDER_READY` | 발주파일 준비됨 | 담당자 | 발주파일 받기 |
| `ORDER_SENT` | 납품 기다리는 중 | 담당자 | 납품명세서 넣기 |
| `RECEIVING` | 납품 검수 중 | 담당자 | 검수 완료하고 작업 끝내기 |
| `COMPLETED` | 완료 | 읽기 전용 | 완료 자료 보기 |

상태 전이는 서버가 검증한다. 모든 변경 요청은 멱등키로 중복 처리를 막고, 편집 가능한 자원은 행 버전 및 `If-Match`로 낙관적 동시성을 검사한다.

## 4. 자료 입력과 원본 보존

### 4.1 공통 입력기

추천목록, 소장목록, 견적서, 발주 출력양식, 납품명세서는 같은 입력기와 문서 인식 체계를 사용한다.

- 파일 시그니처로 실제 종류를 판정하고 확장자 불일치를 경고한다.
- 역할과 헤더를 자동 판정하고, 확신이 낮을 때만 문서 역할을 묻는다.
- 처음 보는 양식은 최대 20행 미리보기로 열 연결을 확인한다.
- `이 양식 기억`은 기본 선택이며 학교·업체·문서 종류·열 구조 조합으로 버전 관리한다.
- 파일별로 진행률, 읽은 책 수, 완료, 확인 필요, 읽지 못함을 표시한다.
- 한 파일의 실패는 다른 파일이나 전체 작업을 취소하지 않는다.
- 읽지 못한 행도 원본 파일, 시트와 행 또는 페이지, 원문, 오류 이유와 함께 `확인 필요`에 남긴다.
- 원본은 SHA-256과 함께 보존한다. 동일 해시와 동일 파서 버전은 재처리하지 않는다.

### 4.2 안전성

입력 단계에서 다음을 차단한다.

- ZIP 폭탄, 경로 탈출, XML 외부 엔터티
- 암호화 또는 손상되어 안전하게 읽을 수 없는 문서
- 엑셀 수식 실행 및 CSV 수식 주입
- 선언된 파일 크기·압축 해제 크기·행 수·페이지 수 제한 초과

수식은 계산하지 않고 원문 또는 저장된 값으로만 취급한다. 내려받기 파일에서 `=`, `+`, `-`, `@`로 시작하는 신뢰할 수 없는 셀은 안전하게 이스케이프한다.

### 4.3 파서

- CSV/TSV/TXT는 인코딩과 구분자를 탐지하고 스트리밍한다.
- XLS/XLSX/XLSB/ODS는 Calamine 계열 빠른 리더를 우선하고 호환되지 않는 파일만 안전한 대체 리더로 처리한다.
- DOCX/HWPX는 ZIP 안의 XML을 안전하게 읽어 표와 문단을 원래 순서에 가깝게 추출한다.
- PDF는 텍스트와 표를 먼저 읽고, 텍스트가 부족한 페이지만 OCR한다. OCR 작업자는 기본 2개로 제한한다.
- HWP는 격리된 내장 리더가 OLE 구조, 본문 스트림, 텍스트와 표 셀을 읽는다. 암호화·손상·지원하지 않는 특수 개체는 HWPX 또는 PDF 변환을 안내하고 원본과 오류를 남긴다.
- MARC는 KORMARC/ISO 2709 레코드를 스트리밍하며 전체 파일을 메모리에 올리지 않는다.

## 5. 내부 표준 도서

정규화된 도서는 다음 정보를 보존한다.

- 제목, 부제, 저자 목록, 출판사, ISBN, 발행일, 가격, 쪽수, KDC
- 권차, 판, 시리즈
- 소장 등록번호, 청구기호, 소장처, 상태
- 추천기관, 목록명, 추천 횟수
- 원본 파일, 시트, 행, 페이지, 원문
- 파서 버전, 양식 버전, 필드별 경고
- 매칭 결과, 점수, 판단 이유, 담당자의 최종 결정

도서 문자열 정규화는 원문을 잃지 않으며 별도 검색 키만 만든다. ISBN-10/13 체크섬을 검증하고 유효한 ISBN-10은 ISBN-13으로 변환한다.

## 6. 장서 원본과 DLS

학교별 활성 장서 원본은 하나만 사용한다. 우선순위는 다음과 같다.

1. `DLS MARC 파일`: 전체 스냅샷과 등록일·갱신일 증분
2. `DLS Excel 파일`: 전체 스냅샷
3. `정식 승인 DLS API`: 승인, 학교 동의, 호환 검증 뒤 활성화

공통 장서 어댑터는 원본을 읽어 `FULL_SNAPSHOT` 또는 `DELTA` 변경 스트림을 만들 뿐 DB를 직접 갱신하거나 도서 매칭을 하지 않는다. 증분은 안정적인 원본 항목 ID가 있을 때만 허용한다.

전체 스냅샷은 임시 버전에서 전량 검증한 뒤 한 트랜잭션으로 활성화한다. 실패·취소·부분 수신 시 기존 장서를 유지한다. 새 장서가 0건이거나 이전 대비 유효 건수가 ±30% 넘게 변하면 자동 활성화하지 않는다.

MARC 증분은 마지막 성공일에서 2일을 겹쳐 입력일·갱신일 파일을 적용한다. 날짜 범위는 `Asia/Seoul` 양끝 포함이며 두 파일이 모두 성공해야 워터마크를 전진시킨다. 갱신일 파일을 충돌 시 우선하고, 증분에 없다는 이유로 기존 항목을 삭제하지 않는다. 90일마다 또는 대량 제적 뒤 전체 스냅샷을 요구한다.

승인 API는 파일 스냅샷과 두 번 연속 비교해 안정 ID 불일치가 `max(20건, 0.5%)` 이하여야 기본 원본으로 승격한다. 승인이 없으면 연동을 노출하지 않는다.

## 7. 비교와 후보 분류

내부 원장은 SQLite WAL을 사용한다. 정확 ISBN과 정규화 키는 인덱스로 찾고, 유사 검색은 전체 장서를 전수 비교하지 않고 검색 인덱스 상위 30건만 정밀 비교한다.

결과 구분은 세 개다.

- `CANDIDATE` / 수서 후보
- `NEEDS_REVIEW` / 확인 필요
- `EXCLUDED` / 제외된 책

판정 규칙은 다음과 같다.

- 유효 ISBN이 활성 장서와 정확히 일치하면 자동 제외한다. 사용자는 되돌릴 수 있다.
- ISBN 없이 정규화 제목과 저자가 일치해도 자동 제외하지 않고 확인 필요로 보낸다.
- 제목, 저자, 권차, 판, 시리즈가 비슷하거나 충돌하면 확인 필요로 보낸다.
- 판본 또는 권차가 다르면 같은 작품이어도 자동 제외하지 않는다.
- 제적·미소장·불확실 상태는 미소장 확정의 근거로 사용하지 않는다.
- 외부 서지 API 보강은 로컬 비교 결과를 먼저 보여준 뒤 백그라운드에서 수행한다.

추천자료의 모든 원본 결과 수 합은 `후보 + 확인 필요 + 제외 + 행 오류`와 같아야 한다. 어떤 행도 오류 때문에 조용히 사라지면 안 된다.

## 8. 승인, 견적, 발주

승인 요청 시 도서, 수량, 단가, 예상 금액, 예산 한도를 변경 불가능한 승인 버전으로 저장한다.

- 승인 대기 중 담당자가 수정하려면 승인 요청을 취소한다.
- 수정 요청 사유는 필수이며 재요청은 새 버전을 만든다.
- 도서 추가, 수량 증가, 승인 예산 초과, 예산 한도 변경은 재승인을 요구한다.
- 도서 제외, 수량 감소, 가격 감소 등 승인 범위 안의 하향 조정은 승인을 유지하고 이력을 남긴다.
- 여러 사용자의 중복 승인·반려 중 최초 성공만 인정한다.

여러 업체 견적서는 총액, 할인율, 품절, 가격 누락, 승인 목록 불일치로 비교한다. 기본은 한 업체 전체 발주이며 분할 발주는 고급 기능이다. 예산 초과 시 프로그램이 책을 임의 삭제하지 않는다.

발주파일은 학교·업체별 기억된 양식을 사용한다. 생성과 다운로드는 한 행동으로 이어지며 실제 주문 전송은 하지 않는다. 사용자에게 `발주파일이 완성되었습니다. 실제 주문 전 업체에 직접 전달해 주세요.`라고 알린다. 전달 확인 뒤 `ORDER_SENT`로 이동한다. 전달 뒤 변경은 기존 파일을 덮지 않고 새 수정본을 만든다.

## 9. DLS 복본조사 내보내기

ISBN 방식은 유효한 ISBN-13 숫자를 중복 제거해 한 줄에 하나씩 기록한다. UTF-8 BOM이 없고 줄바꿈은 CRLF이며 마지막 줄 뒤 추가 줄바꿈은 없다.

서명 XLSX는 시트명 `Sheet1`, 열 순서를 아래와 같이 고정한다.

```text
자료명 | 저자 | 출판사 | 자료유형 | 신청갯수 | 신청자ID | ISBN
```

누락 기본값은 저자·출판사 `미상`, 자료유형 `단행본`, 신청갯수 `1`, 신청자ID `suseoro`, ISBN `0`이다. ISBN은 문자열이다. DLS 결과 `Y`는 `복본 없음`, `N`은 `복본 있음`으로 표시한다.

## 10. 납품과 바코드 검수

납품명세서를 발주 버전과 비교해 다음을 먼저 요약한다.

- 발주했지만 명세서에 없는 책
- 명세서에만 있는 책
- 수량, 단가, 금액 차이
- ISBN 또는 판본 차이

USB ISBN 스캐너는 키보드 입력 방식으로 동작한다. 한 작업에는 활성 스캔 세션 하나만 허용한다. 입력 초점을 유지하고 색상뿐 아니라 큰 문구와 소리로 `확인됨`, `수량 초과`, `미주문`, `판본 차이`를 알린다. 중복 스캔은 멱등으로 처리하며 스캔 이벤트와 결과를 감사 기록에 남긴다.

부분 납품은 여러 차수로 누적한다. 차이는 `VENDOR_CHECK`, `RETURN_PLANNED`, `ADDITIONAL_DELIVERY`, `ACCEPTED` 중 하나로 처리한다. 모든 주문 수량이 확인됐거나 각 차이에 처리 방침이 있어야 작업을 완료할 수 있다.

## 11. API와 공동 편집

외부 경계는 `/api/v2` 아래에 둔다.

- `/auth`: 로그인, 로그아웃, 현재 사용자
- `/workspaces`: 작업 생성, 목록, 상세, 상태
- `/sources`: 업로드, 역할·열 연결, 파싱, 진행률, 재시도·취소
- `/candidates`: 조회, 수정, 일괄 결정, 잠금
- `/approvals`: 버전, 요청, 취소, 승인, 수정 요청
- `/quotes`, `/orders`: 견적 비교, 선택, 발주파일, 전달 확인
- `/deliveries`, `/scans`: 명세서, 차이, 스캔, 완료
- `/events`: SSE 기반 작업·승인·검수 알림
- `/audit`: 사용자, 시각, 변경 전후, 버전 조회

서버 세션은 HttpOnly·Secure·SameSite 쿠키를 사용하고 CSRF를 방어한다. API 키와 인증정보는 Windows DPAPI로 암호화한다. 편집 잠금은 2분이며 다른 편집자를 표시한다. 충돌 시 현재 저장 내용과 사용자의 변경 내용을 함께 반환하며 자동 병합하지 않는다.

## 12. 작업 처리와 복구

`파일 감지 → 파싱 → 열 연결 → 정규화 → 중복 판정 → 검토`는 독립 단계다. CPU 파싱과 OCR은 API 프로세스와 분리된 작업 프로세스에서 실행한다. 작업 상태는 SQLite에 내구성 있게 저장해 서버 재시작 뒤 이어서 처리한다.

취소는 안전한 단계 경계에서 적용한다. 부분 성공 파일과 오류 행은 그대로 남긴다. API의 상태 변경은 같은 멱등키 재시도에서 같은 결과를 반환한다.

## 13. 보안과 운영

- Argon2id 비밀번호 해시, 서버 세션, CSRF, HTTPS
- 교내 사설망만 허용하는 방화벽 설치 안내와 서버 인증서 설치 도구
- 비밀값을 설정 JSON·로그·화면에 평문 노출하지 않음
- 현재 노출된 기존 알라딘 키는 배포 전 폐기·재발급 대상으로 취급
- 매일 백업 및 업그레이드 직전 백업
- 보존: 일간 7개, 주간 4개, 월간 12개
- 업데이트 실패 시 이전 실행본과 DB로 복구
- MSI는 서명 가능한 빌드로 만들며 정식 배포는 조직 코드서명 인증서로 서명된 산출물만 허용

DB 파일을 공유폴더에서 직접 열지 않는다. 모든 사용자는 서버 API로 접근한다.

## 14. v1 이전

이전 마법사는 v1 원본을 수정하지 않고 복사한다.

- 학교 폴더별 학교 생성
- 최신 정상 DLS 원본을 장서 후보로 제시하고 건수 확인 뒤 활성화
- 기존 회차 검수·최종 엑셀을 `이전 버전 작업`으로 읽기 전용 보존
- `catalog_master.xlsx`는 서지 캐시로만 이전하고 소장 판정 근거로 사용하지 않음
- 누락·중복·읽기 실패 건수를 보고서로 제공
- 두 번의 실제 수서 회차 검증 전까지 v1 폴더 삭제를 안내하지 않음
